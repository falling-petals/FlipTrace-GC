# Integrate FlipTrace-GC

The release provides PyTorch replay, cache policy and adaptation components, plus a separate offline evidence checker. Training and evaluation require a caller-supplied GCNet-S implementation, datasets, checkpoint and loop. The integration contract below was checked against the archived sources.

## External inputs

- Use the expanded GCNet-S N=2 graph and its Cityscapes batch-normalization configuration (`gcnet-s_4xb3-120k_cityscapes-1024x1024.py`). The study used an equivalent local PyTorch port. [Pinned GCNet author repository](https://github.com/gyyang23/GCNet/tree/8b4c0abf82cfe13a39ae10d8431a554fc5b3284b)
- Initialize an 11-class, two-head model on CPU under the pair's training seed. Check that the source and target state keys match and that shapes and dtypes match outside the two classifiers. Load the resulting state strictly, keeping the model's new 11-class weights and biases at `decode_head.conv_seg` and `decode_head.aux_cls_seg_c4`. The author's Cityscapes checkpoint labeled 76.9 mIoU has SHA-256 `6da067d1d452350ee82efb9cbb3c67eea3ed6c4b3fe90ca96cc2eaf50a7e99da`. The historical runner used the tensor-only export of the same state, with SHA-256 `0bbeeb67356db642a9032b5327bdb3c2bffab89c2e5a593802b5da4aa88dc728`. [Author checkpoint](https://drive.google.com/file/d/1KersBP95k3b0AELiYlQ1rk4PKUmN-ueu/view)
- Use the pinned SegNet CamVid RGB images and integer-label masks. Use the fixed 37-frame subset A or disjoint subset B for the core pairs, and all 367 official training frames for the E3 eager-cache boundary. Use the training order in [`subset-a.txt`](subset-a.txt) or [`subset-b.txt`](subset-b.txt), and sort official splits by image basename. Use native width 480 and height 360 without crops or padding. Normalize RGB float32 values on the 0–255 scale with mean `(123.675, 116.28, 103.53)` and standard deviation `(58.395, 57.12, 57.375)`. The 11 classes use IDs 0–10 and void uses ID 11. [Pinned SegNet CamVid distribution](https://github.com/alexgkendall/SegNet-Tutorial/tree/fcaf7c4978dd8d091ec67db7cb7fdd225f5051c5/CamVid)

## GCNet split hooks

Place `fliptrace_gc.replay.PrefixReplayMixin` first in the MRO of the external segmentor, as in `class ReplaySegmentor(PrefixReplayMixin, ExternalGCNetSegmentor)`. Provide the following methods and preserve the model's original tensor forward.

| Hook | Required behavior |
| --- | --- |
| `backbone.stage6_inputs(images)` | Return `(detail, semantic, auxiliary)` in that order. The first two are the activated inputs to the last detail and semantic stages, after the second cross-branch fusion. The auxiliary tensor is the detail feature captured just after the first fusion (Stage 4), before its subsequent activation. Preserve it against in-place updates. In training, return all three tensors. The ordinary evaluation path may omit the auxiliary tensor. |
| `backbone.stage6_output(detail, semantic, auxiliary)` | Run both final stages, run the semantic tensor through the context module, upsample it to the detail grid and add the branches. Return `(auxiliary, fused_main)` for training and the fused main tensor for ordinary evaluation. |
| `decode_and_resize(features, size)` | Decode the auxiliary and main features with their corresponding heads. Return `(auxiliary_logits, main_logits)` in training and main logits in evaluation. Resize logits bilinearly to `(height, width)` with `align_corners=False`. |

The expanded graph produced per-view shapes `(64, 45, 60)`, `(256, 12, 15)` and `(64, 45, 60)` with dtypes FP32, FP16 and FP32, respectively, under CUDA FP16 autocast. Preserve the native dtype of each tap and the raw forward's operation order. Each entry is a CPU `uint8` tensor carrying 1,474,560 bytes. The mixin records shapes, dtypes and original geometry while encoding. A raw input is a CUDA `[N, 3, H, W]` tensor and a packed input is a CUDA `[N, bytes_per_view]` tensor. Feed either one into `model(inputs)` under the same CUDA FP16 autocast for training. Keep shape, device, frozen weights, BN buffers and preprocessing stable for the life of a cache. Keep the backbone in training mode to expose the auxiliary tap, with all BN modules individually in evaluation mode.

## Matched 400-update training

1. Prepare `training` as a sorted list of `(basename, normalized_CHW_image, integer_HW_mask)` on the host. Generate 400 batches of 2 from successive shuffled passes. For pass `e` starting at zero, shuffle `list(range(len(training)))` using `random.Random(seed + e)` and append draws to a continuous stream. A batch can straddle passes. Use a separate persistent `flip_rng = random.Random(seed)` and draw `flip_rng.random() < 0.5` once per image occurrence. Build the complete `schedule` of `(training_index, flip_bool)` keys before warm-up, use the same schedule in both arms, and flip both image and mask horizontally. The flip is the only augmentation.
2. Load the same initial model state for each arm, move the model to CUDA and call `torch.manual_seed(seed)` before creating the LoRA factors. Use `fliptrace_gc.adaptation.configure_budget_lora(model)` to freeze the backbone, freeze BN running statistics, and configure the two SGD groups. Train both heads (112,662 parameters) and 357,120 adapter parameters at 24 ungrouped convolutions under `backbone.detail_branch_layers.2` and `backbone.semantic_branch_layers.2`. Each adapter uses rank 12, alpha 24, the base kernel geometry in the down projection and a pointwise up projection. The down projection is initialized uniformly with bound `1 / sqrt(fan_in)` and the up projection starts at zero. The 469,782 trainable parameters include the head BN affine parameters. Use SGD with momentum `0.9`, weight decay `5e-4`, and initial learning rates `5e-4` for the heads and `5e-3` for LoRA.
3. Warm up on the first eight scheduled batches using raw images, at the corresponding first eight learning rates. Restore the full pre-warm-up model state (including adapters and buffers), clear gradients and optimizer state, create a new CUDA `GradScaler`, restore RNG state and start again at the first batch. For measured step `k = 0, ..., 399`, use `base_lr * (1 - k / 400) ** 0.9` for each group. The historical environment used PyTorch 2.7.1 with CUDA 12.6 on an RTX 4060 Laptop GPU, with cuDNN benchmarking and TF32 disabled and four PyTorch CPU threads.
4. After reset, create `fliptrace_gc.replay.BoundedPrefixCache(schedule)` for scheduled replay, or use `use_lru=True` for the matched LRU arm. Obtain inputs once per scheduled step with `cache.inputs(model, training, k, schedule[k])`. A full-batch hit serves the packed tensor. Any miss triggers the original full-batch prefix, packing the result when admitting new entries. The first full hit checks the three replayed tensors and both heads against the raw path with zero tolerance. Scheduled replay retains views with the earliest next use and discards a view at its last use. LRU updates recency in draw order and writes only the net new entries for a batch. Each policy has 45 slots and a 64 MiB tensor payload cap. Use `cache.finish()` after the last update and before stopping the clock. For recomputation, supply the ordinary flipped RGB batch directly. For the eager boundary pairs, prebuild both flips per image after reset using `model.build_prefix_cache(training, schedule[0], before_encode=...)`, with an optional per-image callback, and stack cached rows by key for each update.
5. Stack masks in schedule order as CUDA `long` targets and map void 11 to 255. Use `fliptrace_gc.adaptation.TwoHeadCEDice` on the resized logits with the loss computed in FP32. The objective is main CE plus `0.4 × auxiliary CE + 0.5 × main soft Dice`. CE averages over valid pixels. Dice uses smoothing 1 in numerator and denominator, pools valid pixels across the minibatch and averages over ground-truth-present classes. Batches must contain valid pixels. The archived loop uses CUDA FP16 autocast for the forward and `GradScaler` for the optimizer step. On nonfinite loss or gradient, restore BN buffers and RNG, halve the scale and retry the same inputs and targets, for up to eight retries. Advance the schedule only after a successful update.

Synchronize CUDA and reset peak allocation counters after warm-up reset, then start the training timer before creating the cache. Stop after the last update, bounded-cache cleanup and final CUDA synchronization. This interval includes planning or eager prebuilding, transfers, replay checks, update retries and per-step logging. LoRA merging, checkpoint saving and validation are outside that timer. Report CUDA peak allocated bytes separately from cache tensor payload bytes and the whole-worker peak host working set. The archived 180-second timeout applies to the whole pair's worker, from setup through both 400-update arms, validation and comparison.

## Evaluation and archived commands

After each arm, merge the LoRA update into the corresponding frozen convolution weight. For each target weight `W`, add `2 * (up.flatten(1) @ down.flatten(1)).reshape_as(W)` and replace the adapter with its base convolution. The archived runner checks full-path FP32 logits before and after merging on the first validation frame with `atol=1e-4` and `rtol=1e-4`. Use the final merged weights at 400 updates. The expanded model has 20,694,390 parameters after this merge. For F, both arms share a graph with 26 frozen-prefix GCBlocks folded before warm-up, with construction and numerical verification timed separately. The 24 Stage-6 LoRA sites are preserved and the merged model has 15,071,734 parameters.

Evaluate the full model in evaluation mode using the main logits, CUDA FP32 with autocast and TF32 disabled, batch size 1, and native resolution with no test-time augmentation. Pool an 11-class confusion matrix over the split after excluding void targets. Compute IoU from the pooled matrix and average over classes with nonzero union. Use the 101-image official validation split for each training arm. The locked 233-image test evaluated only the four L1 and L2 checkpoints from update 400 and checked file and checkpoint hashes as well as coverage of 38,719,017 valid pixels.

When the original prepared project workspace is available, use its Windows CUDA environment with AC power and the pinned data and checkpoint paths. From that workspace's root, run `python tools/run_camvid_timed_threeway.py --budget-seconds 180 --run-dir <new-output-dir>` with one flag set below. Each pair requires a fresh output directory.

| R2 | A | Schedule, recompute | `--scheduled-cache --seed 304 --reverse-order` |
